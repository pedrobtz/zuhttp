## 1. HTTP/1.1 uploads between ~32 KiB and 64 KiB are sent twice — #208, high, reproduced

- Where: [src/zuh_engine.c:1183-1194](../../src/zuh_engine.c#L1183-L1194)
- Trigger: `zu_post(u, body = raw(40000))`. The server received
  `Content-Length: 40000` and 80,000 body bytes; 30,000 and 70,000 arrive once.
- Cause: `zuh_buf_append(&wire, body, body_len)` runs inside the first `if`
  condition and grows `wire.len`. The `else if` then re-evaluates
  `body_len > wire.max - wire.len` against the grown buffer and takes the
  "write headers, then write body" path, so the body already appended goes out
  again. Window: `wire.len + body_len <= 65536` and
  `wire.len + 2*body_len > 65536`. `sent_bytes` in the trace is also wrong.
- Fix: make the two paths exclusive by deciding on the original `wire.len`
  before mutating (nest the append inside the first branch, as the diff in
  `2026-11-08-vibe.md` A1 does). Add a byte-counting test at 30,000 / 40,000 /
  60,000 / 70,000.
- Sources: 2026-11-08-codex.md R1-1, 2026-11-08-vibe.md A1.

## 2. An open streamed body is not fork-guarded — #209, high, reproduced

- Where: [src/zuh_engine.c:811-859](../../src/zuh_engine.c#L811-L859)
  (`zuh_open_body_read_within`), `struct zuh_open_body` has no owner PID;
  `src/zuh_net.c` has none either (only `nw_impl` in `zuh_tls_nw.c` does).
- Trigger: `zu_perform(stream = TRUE)` against a server that delays its body,
  then `parallel::mcparallel(zu_resp_read(r))`. The child read `"hello"`;
  the parent's next read failed with
  `zu_http_parse_error: connection closed with 0 of 5 body bytes read`.
- Cause: the pool's §26.4 guard covers idle pooled connections only; a
  connection checked out into a `zuh_open_body` is invisible to it, and
  nothing on the body or stream records which process created it. The child's
  reads consume the parent's bytes, and the child's finalizers close the
  parent's socket.
- Fix: record `zuh_pid_current()` on `zuh_open_body` at creation; refuse
  reads, aborts and finalizers from another PID (leak-and-error, as
  `zuh_tls_nw.c` does), including the HTTP/2 cancel path that writes to the
  connection.
- Sources: 2026-11-08-codex.md R1-2, 2026-11-08-vibe.md B1.

## 3. Malformed chunk framing is delivered to the body sink before the parse error — #210, medium, reproduced

- Where: [src/zuh_body.c:208-214](../../src/zuh_body.c#L208-L214),
  [src/zuh_response.c:199-206](../../src/zuh_response.c#L199-L206)
- Trigger: chunked body `X\r\nATTACK\r\n0\r\n\r\n` with a `callback`. The
  callback received the raw wire bytes `X\r\nATTACK\r\n0\r\n\r\n` and only
  then did the request raise `zu_http_parse_error`. With `3\r\nabc\r\n` in
  front, the callback received `abc` followed by the same garbage.
- Cause: `zuh_chunked_decode()` returns `ZUH_ERR_PARSE` on `rc == -1` before
  the `*len = n` assignment, so `len` keeps its input value (the wire length).
  `zuh_body_reader_step()` then does `if (len) zuh_body_pipe_feed(...)` before
  looking at `rc`.
- Fix: on any non-OK result other than `WOULDBLOCK`, set `*len = 0` in the
  decoder (or check `rc` before feeding). Define the contract: after an error,
  no output bytes are valid.
- Note: `2026-11-08-vibe.md` reports this as FIXED; it is not, on this checkout.
- Sources: 2026-11-08-codex.md R1-3.

## 4. Repeated `Content-Encoding` fields decode once and erase the evidence — #211, medium, reproduced

- Where: [src/zuh_body.c:27-28](../../src/zuh_body.c#L27-L28),
  [src/zuh_body.c:45](../../src/zuh_body.c#L45)
- Trigger: two `Content-Encoding: gzip` fields and a body of `gzip(gzip("hello"))`.
  `zu_resp_raw()` returned 25 bytes starting `1f 8b` (still gzip), and
  `zu_resp_header(r, "Content-Encoding")` returned nothing.
- Cause: `zuh_headers_get()` returns the first field only; the pipe inflates
  once, then removes every `Content-Encoding` header.
- Fix: count the fields; more than one is a stacked encoding, which §21.4
  already refuses for a `gzip, br` *value*, so refuse the multi-field case the
  same way (`ZUH_ERR_BODY_DECODE`).
- Sources: 2026-11-08-codex.md R1-4, 2026-11-08-vibe.md B2.

## 5. `max_body` binds compressed bytes under chunked framing, decoded bytes under Content-Length — #212, medium, reproduced

- Where: [src/zuh_body.c:133](../../src/zuh_body.c#L133)
  (`zuh_chunked_init(&r->dec, 0, max_body)`),
  [src/zuh_response.c:215-223](../../src/zuh_response.c#L215-L223)
- Trigger: the same gzip stream decoding to `"hello"` with `max_body = 5`:
  Content-Length framing returns `hello`; chunked framing raises
  `zu_body_limit_error`.
- Cause: the chunk decoder's `max_total` is given `max_body` and applied to
  the de-chunked, still compressed payload (25 bytes) before inflation; the
  design (§40, the options table) says `max_body` is a cap on decoded bytes.
- Fix: pass `0` (or a separate wire cap) as `max_total`; `cap_check()` and
  `zuh_inflate`'s `max_out` already enforce the decoded cap on every sink.
- Sources: 2026-11-08-codex.md R1-5, 2026-11-08-vibe.md B3.

## 6. `zu_resp_abort()` is a no-op once the wire has ended, so undelivered bytes stay readable — #213, medium, reproduced

- Where: [src/zuh_engine.c:861-862](../../src/zuh_engine.c#L861-L862)
- Trigger: `Content-Length: 5`, `stream = TRUE`; `zu_resp_read(r, 1)` gives
  `"h"`, `zu_resp_abort(r)`, `zu_resp_read(r)` gives `"ello"` instead of
  `zu_cancelled_error`.
- Cause: the early return on `b->ended` treats "finished receiving" as
  "nothing to abort"; `b->aborted` is never set, and the read path serves the
  staged remainder. `zuh_open_body_done()` already distinguishes the two.
- Fix: drop `b->ended` from the early return; set `b->aborted = 1` whenever
  the caller has not had everything, then release as today (the release is
  already a no-op after end).
- Sources: 2026-11-08-codex.md R1-6, 2026-11-08-vibe.md B4.

## 7. A failing `Rf_allocVector()` in `C_zu_stream_read` leaks the native `got` buffer — #214, medium, inspection

- Where: [src/init.c:1394-1398](../../src/init.c#L1394-L1398)
- Cause: `got` owns heap memory when `Rf_allocVector(RAWSXP, got.len)` runs;
  an allocation failure longjmps past `zuh_buf_free(&got)`. The comment says
  the buffer is "freed on both sides of it", but only the success side frees.
  It is the one C-owned resource in `init.c` across an R allocation without an
  `R_UnwindProtect` companion (`build_response` has one).
- Fix: run the conversion under `R_UnwindProtect` with a cleanup that frees
  `got`, as `free_result_on_unwind` does for `build_response`.
- Sources: 2026-11-08-codex.md R1-7, 2026-11-08-vibe.md B5.

## 8. The OpenSSL backend keeps a pointer to the engine's stack-local `zuh_tls_config` — #215, high, inspection (ASan-reproduced in the Codex round)

- Where: [src/zuh_tls_openssl.c:345](../../src/zuh_tls_openssl.c#L345)
  (`t->cfg = cfg`), read in `verify_cb` at
  [src/zuh_tls_openssl.c:134-136](../../src/zuh_tls_openssl.c#L134-L136);
  the config is a local at [src/zuh_engine.c:514-521](../../src/zuh_engine.c#L514-L521).
- Cause: `verify_cb` runs again on TLS 1.2 renegotiation, after `open_direct`
  has returned; by then `cfg`, and the pin strings it points to, are gone.
  Reading `t->cfg->n_pins` is already a use-after-return with no pins
  configured. No `SSL_OP_NO_RENEGOTIATION` is set. The Codex round reproduced
  `stack-use-after-return in verify_cb()` under ASan with a renegotiating
  loopback server; it was not re-run here because the macOS build uses
  Network.framework.
- Fix: copy what `verify_cb` needs (pins included, deep-copied) into
  `tls_impl` at connect time, and/or set `SSL_OP_NO_RENEGOTIATION`. Audit
  every pointer a connection retains for the same ownership question.
- Sources: 2026-11-08-codex.md R2-1, 2026-11-08-vibe.md B6.

## 9. IP-literal URLs cannot verify under OpenSSL — #216, medium, inspection (reproduced in the Codex round)

- Where: [src/zuh_tls_openssl.c:388-394](../../src/zuh_tls_openssl.c#L388-L394)
- Cause: every target goes through `X509_VERIFY_PARAM_set1_host()`, which
  matches DNS names only; OpenSSL's documentation says an IP address must be
  set with `X509_VERIFY_PARAM_set1_ip()`/`set1_ip_asc()` so that verification
  invokes `X509_check_ip()`. A certificate with `IP:127.0.0.1` therefore
  verifies for `localhost` but not for `https://127.0.0.1/`.
- Fix: detect an IP literal (the URI parser already knows) and call
  `X509_VERIFY_PARAM_set1_ip_asc()` instead; skip SNI for IP literals.
- Sources: 2026-11-08-codex.md R2-2, 2026-11-08-vibe.md B6.

## 10. A request body function that returns only empty pieces runs past the request timeout — #217, medium, reproduced

- Where: [src/init.c:138-168](../../src/init.c#L138-L168) (`src_next`)
- Trigger: `timeout = 0.2`, a `zu_body_stream()` function returning `raw()`
  150 times with 10 ms sleeps: the request took 1.86 s and the function was
  called 151 times before `zu_timeout_error`.
- Cause: the empty-piece loop checks interrupts between pieces but never the
  attempt deadline; the engine only notices the deadline on a write, and empty
  pieces never write.
- Fix: carry the attempt deadline in `src_ctx` and return `ZUH_ERR_TIMEOUT`
  from the loop when it has passed.
- Sources: 2026-11-08-codex.md R2-3, 2026-11-08-vibe.md B7.

## 11. The retry loop aborts a streamed response before deciding whether it can retry — #218, medium, reproduced

- Where: [R/perform.R:532-544](../../R/perform.R#L532-L544)
- Trigger: `stream = TRUE`, `check = FALSE`, `timeout = 1`,
  `zu_retry(attempts = 3, base = 2)` against a 503 server. The call returned
  the 503 after one attempt, and `zu_resp_read()` on it raised
  `zu_cancelled_error`: the server's body is gone.
- Cause: `zu_resp_abort(resp)` runs before the §33.3 budget check
  (`left <= 0 || delay >= left`), which then breaks and returns the aborted
  response.
- Fix: compute `delay` and `left` first; abort only when the loop is going to
  sleep and retry.
- Sources: 2026-11-08-codex.md R2-4, 2026-11-08-vibe.md B8.

## 12. `query =` parameters vanish when the URL carries a fragment — #219, medium, reproduced

- Where: [R/url.R:93-101](../../R/url.R#L93-L101) (`url_with_query`)
- Trigger: `zu_get("http://host/path#section", query = list(x = "hello"))`
  sent `GET /path HTTP/1.1`; without the fragment the same call sent
  `GET /path?x=hello HTTP/1.1`.
- Cause: the query string is appended after the whole URL, i.e. inside the
  fragment, and `?`/`&` is chosen by scanning the fragment too. The C URI
  parser then drops the fragment, parameters included, and nothing errors.
- Fix: split on the first `#`, append to the pre-fragment part, choose the
  separator on that part, re-attach the fragment (or refuse fragments in
  request URLs).
- Sources: 2026-11-08-codex.md R2-5, 2026-11-08-vibe.md B9.

## 13. `zu_resp_method()` reports the original method after a 303 rewrite — #220, low, reproduced

- Where: [R/perform.R:445](../../R/perform.R#L445) (`resp$method <- r$method`)
- Trigger: `zu_post(u, body = "x")` answered `303 Location: /final`; the
  server saw `POST /` then `GET /final`, and `zu_resp_method(r)` said `"POST"`.
- Cause: the method is copied from the request; the engine's rewritten method
  never comes back (`zuh_result` has no method field), although the roxygen
  for `zu_resp` promises "the method actually sent, which a 303 may have
  rewritten to `GET`".
- Fix: add a `final_method` to `zuh_result`, set it where `perform_hops`
  rewrites the method, and read it in the native transport.
- Sources: 2026-11-08-codex.md R2-6, 2026-11-08-vibe.md B10.

## 14. `redirects` above `.Machine$integer.max` silently disables redirect following — #221, medium, reproduced

- Where: [R/perform.R:309-316](../../R/perform.R#L309-L316) (validation),
  [R/perform.R:111](../../R/perform.R#L111) (`as.integer(p$redirects)`),
  [src/init.c:867](../../src/init.c#L867)
- Trigger: `zu_get(u, redirects = 1e10, check = FALSE)` against a 302
  returned the 302 itself with only a coercion warning; the server saw no
  second request.
- Cause: `as.integer(1e10)` is `NA_integer_`; C reads `INT_MIN`, which fails
  every `max_redirects > 0` test. `zu_pool()`'s `check_count()` guards exactly
  this; `redirects` does not.
- Fix: add `policy$redirects > .Machine$integer.max` to the check (and treat
  `Inf` the same way, or document it as "unlimited" and clamp).
- Sources: 2026-11-08-vibe.md A2.

## 15. `zu_retry(attempts = )` above `.Machine$integer.max` is accepted and then breaks every request on the client — #222, medium, reproduced

- Where: [R/retry.R:58-69](../../R/retry.R#L58-L69), [R/retry.R:78](../../R/retry.R#L78),
  consumed at [R/perform.R:489](../../R/perform.R#L489) and
  [R/perform.R:517](../../R/perform.R#L517)
- Trigger: a mock transport returning 200 and
  `zu_client(retry = zu_retry(attempts = 1e10))`: every request fails with
  "missing value where TRUE/FALSE needed".
- Cause: same class as item 14; `NA > 1L && TRUE` is `NA`, and `if (NA)`

- Fix: add `attempts > .Machine$integer.max` to the validation (and
  `is.finite()`), as `zu_pool()` does.
- Sources: 2026-11-08-vibe.md A3.

## 16. The chunk decoder's `max_chunk` bound is dead in production — #223, low, inspection

- Where: [src/zuh_response.c:106](../../src/zuh_response.c#L106),
  [src/zuh_response.c:225-231](../../src/zuh_response.c#L225-L231); the only

## Cross-cutting

- Items 1, 3, 5, 6 share one shape: a helper is correct on its own and the
  composition breaks the contract (headers-vs-body send paths, decoder result
  vs sink feed, wire bytes vs decoded bytes, received vs delivered).
- Items 2 and 8 are ownership gaps: a connection outlives the frame or the
  process that created it, and nothing on it says who owns it.
- Items 14 and 15 are the one validation `zu_pool()` has and the other
  integer-valued policies lack.

## Suggested regression tests (one per item)

1. Byte-counting POST at 30,000 / 40,000 / 60,000 / 70,000 bytes.
2. Fork with an open streamed body; the child's read must error, the parent's
   must still succeed.
3. `X\r\n...` chunk with a callback; the callback must receive 0 bytes.
4. Two `Content-Encoding: gzip` fields must raise `zu_body_decode_error`.
5. The same gzip body under both framings with `max_body` equal to the
   decoded size must succeed in both.
6. Read 1 byte, abort, read again must raise `zu_cancelled_error`.
7. `gctorture()`-style allocation failure in `zu_resp_read()` under the
   ctest allocation-balance oracle.
8. OpenSSL: a renegotiating loopback server under ASan (the Codex round's
   `/tmp/zuhttp-review2-tls.py`).
9. OpenSSL: a trusted certificate with `IP:127.0.0.1`, fetched by IP.
10. A body function returning `raw()` forever with `timeout = 0.2` must
    raise within the budget.
11. A streamed 503 with a retry delay longer than the remaining budget must
    come back readable.
12. `#fragment` plus `query =` must put `?x=...` on the request line.
13. `zu_resp_method()` after a 303 must be `"GET"`.
14. `redirects = .Machine$integer.max + 1` must `stop()`.
15. `zu_retry(attempts = .Machine$integer.max + 1)` must `stop()`.
16. (none; remove or wire the parameter.)
